# Issue 10: 实现主题 Wiki 与知识图谱

Status: ready-for-agent
Type: task
Blocked by: 01, 02, 04, 05, 11

## 目标

根据管理员发布的博客文章建立按主题组织的 Wiki 页面。管理员在后台维护和审核 Wiki；访客及读者通过公开知识图谱浏览已发布主题页。Wiki 用于长期整理和发现知识，博客文章仍是权威原文。

## 页面与权限

- Wiki 页面按主题组织，有标题、稳定 slug、经审核正文、相关 Wiki 页面、支持它的具体已发布文章版本和版本历史。
- 现有博客文章首页和文章列表保持不变；网站增加独立 Wiki 入口。访客及登录读者可浏览公开知识图谱和已发布主题页，只读，不可查看草稿或管理功能。
- 管理员在 `/admin/wiki` 查看、创建、编辑、审核和合并 Wiki 页面；管理员可查看候选草稿、版本记录，以及发布草稿后知识图谱的预览。
- 合并主题须形成可审核的新页面版本；保留历史，并为被合并页面提供受控跳转或历史访问行为。
- Wiki 页面的 AI 候选正文、来源绑定及页面关系均需管理员审核后才公开。聊天式问答回答是即时结果，不走 Wiki 页面审核流程。

## 创建与更新

- 初次启用时，以全部当前已发布文章为输入生成 Wiki 主题页候选草稿；不得将候选草稿直接公开。
- 文章发布或新版本发布成功后，异步生成受影响的 Wiki 页面及主题关系候选更新，不阻塞文章发布。页面更新失败时保留原已发布版本。
- 管理员按受影响的页面审核候选正文、来源和链接变化；接受、修改或拒绝一个页面的更新只影响该页面及其待审核关系，不改动无关页面。
- 页面必须关联至少一个当前有效的已发布文章版本。文章下架、删除或新版本替换后重新验证来源；失去全部当前有效来源的页面从公开图谱和问答检索隐藏，管理员可补充来源后重新审核发布。
- 新页面、来源变更和页面关系候选在管理员审核前不进入公开知识图谱或问答检索。图谱只由已发布页面和已审核关系生成。

## 搜索与集成

- 首版使用 PostgreSQL 搜索 Wiki 页面和文章原文片段，不引入向量数据库。
- Issue 07 的管理员问答优先检索已发布 Wiki 页面；Wiki 证据不足时只检索少量相关已发布文章原文片段，绝不将全部文章发送给模型。回答引用仍映射到文章版本，证据不足时拒答。
- Wiki 生成和问答均遵守 DeepSeek API 专属数据处理政策门槛；政策未核实或不符合负责人接受条件时，不得向供应商发送问题、Wiki 内容或文章内容。
- 上游 `nashsu/llm_wiki` 是本地优先桌面应用，不作为线上服务依赖；可参考其主题组织与关联知识思路，不复用其应用数据和 API 运行时。
- Wiki 更新只记录必要的模型用量信息；不设问答/Wiki 共用的应用月度费用预算或费用告警。

## 验收标准

- 当前所有已发布文章都会进入首次候选生成输入；草稿、下架和删除文章不进入候选内容。
- 管理员能在 `/admin/wiki` 手动新建、编辑、合并页面，审核 AI 候选页面与关系，并查看版本历史；普通访客和读者不能访问后台、草稿或写操作 API。
- 文章发布成功不等待 Wiki 生成或审核；更新失败、拒绝或待审核期间继续使用现有页面版本。
- 审核按页面生效；测试证明一页的决定不会覆盖或修改无关页面。
- 公开图谱只含已发布页面与已审核关系；点击节点可打开主题页；现有文章首页及文章路由保持可用。
- 页面失去全部有效文章版本来源后，不出现在公开图谱或问答检索结果；保留其他有效来源的页面仍可见。
- Wiki 搜索使用 PostgreSQL，不要求向量数据库；部署不要求运行上游桌面应用。
- Wiki 生成调用受 DeepSeek 数据政策功能开关保护；API 凭据不进入浏览器、响应或日志。
- 更新有关功能后运行 `npm test`，并按仓库门禁运行 `npm run lint`、`npm run typecheck` 和 `npm run build`。
