# Issue 11: 拆分管理员工作台并完善账号管理

Status: ready-for-agent
Type: task
Blocked by: 04, 05

## 目标

把当前混合读者账号操作、文章上传和文章列表的管理员长页面拆成清晰的管理入口，并补齐人工维护读者资料的能力。

## 范围

- `/admin` 作为管理员工作台/导航入口，提供账号管理、文章管理、AI 设置与问答的独立入口；没有必要的数据概览时不添加装饰性仪表盘指标。
- 将读者账号管理放在独立页面，支持人工创建 reader、按状态/邮箱/昵称检索和查看、编辑昵称及登录邮箱、启用/停用、管理员线下确认后的临时密码重置。
- 编辑邮箱时按大小写不敏感唯一性校验，并要求填写原因；成功修改后撤销目标用户现有会话并审计前后邮箱快照。昵称修改审计前后值和原因。
- 状态更改与临时密码重置沿用现有服务与审计规则；停用撤销会话，重新启用不恢复旧会话。
- 角色不可通过编辑表单修改；公开注册仍只创建 reader；该页面不得删除管理员账号，也不提供批量危险操作。
- 文章上传/版本列表/预览/发布/下架/删除/恢复归独立文章管理页面，保留 Issue 05 的权限和版本不变量。
- AI 模型配置、预算状态和问答界面归独立 AI 页面；问答仅 admin 可用，详细行为由 Issue 07 定义。
- 管理区和写 API 由服务端每次验证 active admin；所有变更记录操作者、目标、时间、原因及适用的前后值。

## 验收标准

- `/admin` 只呈现管理功能导航，不再同时渲染读者表单、上传表单和完整文章版本列表。
- 每个管理区域有独立路由；直接访问和 API 请求均由服务端授权，reader/匿名用户不能取得管理数据。
- 管理员可以查找并编辑 reader 昵称/邮箱；重复邮箱、无效输入、空原因和数据库错误有安全提示且不泄漏内部信息。
- 邮箱更改后旧会话失效；账号状态和资料变更审计可核验，角色不可被修改。
- 文章管理和 AI 页面按各自 Issue 提供能力，不复制数据仓储或授权逻辑。
- 响应式与可访问性检查通过；运行 `npm run lint`、`npm run typecheck`、`npm test`、`npm run build`。
