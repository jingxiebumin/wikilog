# Issue 08: 完成首发安全、恢复与发布检查

Status: ready-for-agent
Type: task
Blocked by: 01, 02

## 目标

验证匿名公开博客及各项登录功能在生产配置下安全、可恢复、费用可观察，并落实分能力功能开关。匿名发布、账号/收藏、管理员管理操作和问答各自独立验收；一项能力未通过不阻塞其他已通过验收的能力。匿名最低验收先依赖 Issue 01 与本 Issue 的公开读取/备份恢复检查。

## 验收标准

- **匿名最低验收**：Issue 01 的目标环境、持久化/恢复和访问验证通过；本 Issue 完成匿名读取边界、生产密钥配置、PostgreSQL 与文章图片备份/恢复演练及回滚检查。通过后只允许开放匿名只读博客。
- **账号/收藏验收**：在匿名最低验收基础上，Issue 04、06 完成；验证注册/登录、reader/admin 收藏及账号管理端点有授权、限速、审计和输入校验。通过后可开放 IP/HTTP 账号与收藏，不要求 Issue 07 完成。
- **管理员管理验收**：Issue 05、11 完成；验证文章上传、版本切换和读者资料修改端点均有管理员授权、限速、审计及回滚能力。通过后按管理功能单独开放。
- **问答验收**：Issue 07 完成并验证供应商数据政策、费用、配额、引用和故障处理；reader/匿名被拒绝，问答和会话仅 active admin 可用。未通过时仅关闭问答，不连带关闭已验收的账号和收藏。
- 数据库故障、对象存储故障和模型超时均有安全降级，不泄漏内部数据；系统不发送邮件。
- 有 PostgreSQL 和文章图片的备份/恢复流程，并完成一次恢复演练。
- 记录网站/数据库实际成本核验方式；记录模型供应商用量与应用估算对账方式及告警阈值。
- 匿名最低门槛通过后可单独部署公开博客；账号/收藏在各自授权与限速验收通过后按 IP/HTTP 目标开放；问答仅在 admin 授权、模型政策和预算门槛通过后开放。
- 对已启用能力完成匿名、reader、admin 角色端到端验收，并执行 lint、类型检查、测试和生产构建；问答单独验收 admin-only 边界。

## Comments

2026-11-11：根据代码盘点和负责人决定拆分发布门槛。当前尚无生产部署、对象存储、备份恢复、问答或 Wiki 实现；本 Issue 是未来目标环境验收，不代表这些能力已通过。Issue 03 已关闭，不是此 Issue 的技术依赖。

- **业务目标与领域规则**：保护匿名公开博客及后续读者功能的生产启用。只有负责人本人是唯一管理员；服务端是认证、角色、所有权、开关和发布判断的权威来源。基础设施成本按服务器真实订单、续费价和按量费用记录；问答/Wiki 另共用 `¥20/月` 应用预算。
- **状态流转**：匿名最低验收依赖 Issue 01、02；账号/收藏验收另依赖 Issue 04、06；管理员管理验收另依赖 Issue 05、11；问答验收另依赖 Issue 07。各能力按自己的门槛分别开放或关闭，失败不连带关闭已通过验收的其他能力。
- **权限边界**：匿名只能访问当前公开版本；active reader 只能访问自己的个人数据；唯一管理员执行文章及设置操作；任何角色均需服务端复核。密钥只存在服务端配置，日志与错误不得泄露凭据、内部异常或敏感问答。
- **正常流程**：先对目标环境执行匿名发布最低门槛并记录结果；然后按账号/收藏、管理操作、问答各自依赖执行验收；记录匿名/reader/admin E2E、备份恢复、成本/模型对账、开关状态与回滚步骤。恢复后校验文章/版本指针与图片引用一致。
- **异常与边界**：数据库、图片存储或模型故障使用安全降级；已发布文章读路径不得显示草稿；备份恢复失败或数据/图片不一致时不开放对应写功能；模型政策、预算或凭据不满足时问答/Wiki 关闭；系统不发送邮件。
- **依赖**：匿名最低验收依赖 Issue 01、02；账号/收藏验收依赖 Issue 04、06；管理员管理依赖 Issue 05、11；问答依赖 Issue 07。Issue 03 已 `wontfix`，不构成依赖。09/10 的 Wiki 上线另受各自评估、批准及生产门槛约束。
- **可验证验收**：分别留存匿名、账号/收藏、管理员管理和问答验收记录；每份记录列明对应 Issue、启用开关、三角色预期与实测结果、密钥扫描、备份/恢复/回滚、成本或模型用量核验及质量门禁。问答验收明确 reader/匿名拒绝而 active admin 允许。RPO/RTO、备份保留期和告警阈值在目标服务能力确认后由负责人批准并记录，不能预设为已达到。
