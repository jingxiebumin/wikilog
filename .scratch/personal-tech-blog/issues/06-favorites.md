# Issue 06: 实现收藏与读者数据生命周期

Status: ready-for-agent
Type: task
Blocked by: 04, 05

## 目标

实现所有已登录用户（reader/admin）各自的收藏列表，并在账号删除时清理该用户的收藏数据。

## 验收标准

- 每位 active 登录用户（reader/admin）对每篇文章最多有一条收藏；并发重复请求不会生成重复数据。
- 收藏列表按最近收藏时间倒序；草稿/下架文章隐藏，重新发布后原收藏恢复。
- reader/admin 只能列出、创建和删除自己的收藏；后端验证服务端会话及所有权。
- 账号删除时删除该账号的收藏数据；后续功能新增个人数据时须扩展删除级联。
- 覆盖重复收藏、他人数据访问、文章下架/重发和账号删除收藏清理的测试。

## Comments

2026-11-11：补充与当前文章及读者模型一致的实现规格；当前没有收藏表、模块、路由或测试。

- **业务目标与领域规则**：收藏是某读者与稳定 `article_id` 的关系，不绑定易变 slug 或文章版本；每个读者/文章组合唯一，收藏列表按 `created_at` 最近优先。
- **状态流转**：只能对当前公开文章创建收藏；移除即删除关系。文章下架或删除期间隐藏但保留关系；恢复/重新发布后原收藏和收藏时间恢复。V1 不提供文章永久删除。账号硬删除时收藏随用户级联删除。
- **权限边界**：身份只来自服务端会话；active reader 和 admin 均可创建、列出、删除自己的收藏。匿名用户不可用；任何角色均不能访问他人收藏；不得信任客户端传入 user ID。
- **正常流程**：登录读者对当前公开文章收藏；列表仅返回其收藏中当前可公开读取的文章，按收藏时间倒序；移除后不再出现。
- **异常与边界**：重复并发创建由唯一约束保证仅一条，重复请求维持原收藏时间；不存在或非公开文章不得通过错误响应泄露草稿/下架内容；数据库错误采用安全通用响应。
- **依赖**：依赖 Issue 04 的读者会话与账号删除级联、Issue 05 的稳定文章 ID/下架恢复状态。Issue 08 对收藏端点做生产授权和恢复验收。
- **可验证验收**：迁移唯一约束；并发重复添加不重复且不改初次收藏时间；跨读者读/删拒绝；草稿/下架/删除文章不能新收藏且现有收藏隐藏；恢复后收藏时间不变；账号删除级联；`npm test` 覆盖上述流程。
- **待确认**：无永久删除意味着收藏外键可长期保留；若未来引入文章永久删除，需单独决定其收藏关系与审计清理策略，不由本 Issue 推断。
