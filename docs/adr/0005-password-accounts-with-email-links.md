# ADR-0005：密码账号不依赖邮件服务

状态：已修订（2026-11-14）

## 背景

项目不接入邮件供应商。邮箱作为登录名，但不代表邮箱归属已验证，也不发送注册、验证、修改或重置邮件。原方案采用管理员线下确认身份并生成一次性随机临时密码；该密码恢复方式已由负责人明确改为固定初始密码和强制首次改密。

## 决策

- 邮箱为大小写不敏感的登录名和人工联系字段，不证明邮箱归属；系统不发送邮件。
- 管理员创建读者时只填写邮箱，初始密码固定为 `123456`。管理员重置密码也设为 `123456`，须由管理员在界面二次确认并提示将设置为该值；不进行线下身份确认，也不要求填写重置原因。
- 使用初始密码或重置密码登录的读者，首次登录必须设置昵称并修改为自己的新密码后才能继续使用系统。
- 读者本人修改邮箱时需填写当前密码；管理员修改读者邮箱不要求读者密码。两种邮箱修改均仅与未软删除账号做大小写不敏感唯一性校验，不发送验证邮件，并撤销目标读者的全部会话；本人修改成功后跳转登录。
- 密码始终以成熟的带盐哈希保存，不保存明文。初始/重置密码本身不写入逐次操作日志。
- 公开注册永远只能创建 `reader`；管理员账号只能受控初始化。认证、角色校验、限速和通用错误处理均在服务端执行。

## 取舍

不使用邮件服务意味着系统不证明邮箱所有权，也没有邮件自助找回流程。固定初始密码易于线下告知，因此首次登录强制设置昵称和新密码，并在重置时撤销原有会话。该固定密码仅用于首次登录或管理员重置，不代表读者的长期密码策略。

## 历史修订

2026-11-07 的初始版本规定管理员线下确认身份、生成一次性随机临时密码并记录重置审计。2026-11-14 的负责人决策取代上述重置规则；原始规则仅作为历史决策记录，不再是实施要求。
