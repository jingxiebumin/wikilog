# ADR-0007：头像存放在华为云服务器私有持久目录

状态：已接受（2026-11-14；2026-11-21 修订）

## 背景

用户头像属于仅本人可见的个人信息。2026-11-14 决策时，项目已有的 `/srv/wikilog/uploads` 目录曾验证可跨容器重建和主机重启保留样例文件，但以只读方式挂载给 Web 容器，真实头像上传流程尚未验证。对话附件中出现的 `/srv/wikilog/uploads/avatars` 是示例路径，不是已确认的目录选择。2026-11-21 已另行完成头像隔离上传与授权读取验收，具体路径和结果见本 ADR 修订记录。

## 决策

- 头像文件存放在已购买的华为云服务器上的私有持久目录，不为头像单独引入对象存储服务。
- 头像目录不直接作为公开静态资源。服务端必须验证会话和资源归属，仅向头像本人提供读取；管理员不能查看读者头像。
- 实际目录路径、容器挂载位置和权限按目标服务器实测确定，不将附件中的示例路径视为已选目录。
- 头像上传实施前，必须验证应用写入、本人鉴权读取、非本人拒绝读取及 Web 容器重建后的可读性。Docker daemon 和主机重启测试须先列明影响并获负责人单独批准。
- 不使用 CloudBase、COS 或其他头像存储服务。
- 图片上传和展示限制按 Issue 11：静态 JPEG、PNG 或 WebP，单张不超过 5 MB；默认使用通用头像图标，用户可上传或更换但不能移除已上传头像。

## 后果

- 头像保存在服务器文件系统并由服务端授权读取；部署须控制目录写权限，禁止匿名直读。
- 验收完成前不启用生产头像上传功能。验收须记录最终目录和权限、上传/读取授权结果及 Web 容器重建后的可读性；使用 localhost 隔离验收实例及测试数据库，不启用生产账号。
- 该决策只覆盖用户头像，不自动决定文章配图或其他上传文件的存储方案。

## 2026-11-21 修订

负责人确认 CBR 已切换到华南-广州，但决定不购买 CBR 存储库、不配置头像备份且不做恢复演练；明确接受服务器系统盘故障导致头像丢失的风险。2026-11-11 的数据库备份恢复与目录重启记录保留为历史事实，不记作头像备份或恢复验收。

根据目标服务器实测，现有 `/srv/wikilog/uploads` 属主 `codex:codex`、权限 `0755`，并以只读方式挂入 Web；应用用户 `nextjs` 为 `1001:1001`，不能写入。该目录在系统盘 `/dev/vda1`。头像使用同级专用目录 `/srv/wikilog/private-avatars`，属主 `1001:1001`、权限 `0700`，读写挂载到容器非公开静态路径 `/var/lib/wikilog/private-avatars`。系统盘故障丢失头像风险已接受。

生产 `AUTH_ENABLED` 保持 `false`，AI 问答和 Wiki AI 生成继续关闭。2026-11-21 在 localhost 隔离验收实例及独立测试数据库中完成上传写入、本人读取、非本人拒绝读取和隔离 Web 容器重建可读性验证；生产 Web 容器随后重建并健康检查通过，未重启 PostgreSQL。生产 `AVATAR_STORAGE_VERIFIED` 已在这些检查通过后开启。Docker daemon 和主机重启测试尚未执行，须另行批准；不配置头像备份或恢复演练。

验收结果：上传返回 200；文件属主 `1001:1001`、模式 `0600`；本人读取返回 200 且内容校验一致，其他 reader 返回 404，匿名返回 401；隔离 Web 容器重建后仍可读取。生产挂载 `/srv/wikilog/private-avatars` → `/var/lib/wikilog/private-avatars` 为读写，目录 `1001:1001`/`0700`，运行用户 `nextjs` UID/GID `1001:1001` 可写。头像目录位于系统盘 `/dev/vda1`；负责人接受系统盘故障导致头像丢失的风险。
