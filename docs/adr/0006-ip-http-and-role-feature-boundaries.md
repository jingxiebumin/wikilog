# ADR-0006：公网 IP/HTTP 与角色功能边界

状态：已接受（2026-11-13）

## 背景

负责人决定不申请域名、不做备案、不配置 HTTPS，也不使用或验证 CloudBase。此前文档曾把 HTTPS 作为账号、收藏和公网写操作的统一关闭条件。负责人现在明确要求公网 IP/HTTP 目标下仍可注册账号和收藏文章，并限制问答只对管理员开放。

## 决策

- 目标公网访问形式为公网 IP/HTTP；域名、备案、HTTPS 和 CloudBase 不属于本项目计划事项或功能开关条件。
- HTTP 不加密传输。登录凭据和会话可能被路径上的网络节点观察或篡改。负责人接受此传输风险；文档和产品不得把 HTTP 描述成安全传输。
- 公网账号注册/登录允许启用，但仍须服务端身份验证、账号/邮箱/IP 限速、通用错误响应和安全 Cookie 配置。
- 会话 Cookie 保持 `HttpOnly`、`SameSite=Lax`；HTTP 请求的 `Secure` 必须为 false 才能建立会话，HTTPS 请求设为 true。负责人接受 HTTP 下缺少传输加密保护的风险。
- 所有 active 登录用户（reader/admin）均可添加、查看和移除自己的文章收藏；数据访问按当前服务端用户 ID 隔离。
- 问答只对 active admin 开放。管理员只能访问自己创建的问答会话；reader 与匿名请求必须在服务端拒绝。DeepSeek 政策、预算、配额、来源校验和故障处理仍是问答启用条件。
- 管理员文章和账号写操作由服务端管理员授权、限速与审计保护，不因 HTTP 自动关闭。公网开放前仍须完成目标网络、持久化、备份恢复和分角色验收，并核对云平台对当前实例及访问方式的适用要求。

## 后果

- HTTP 下凭据和会话存在中间人观察/篡改风险；本决策是负责人对风险的明确接受，不是 HTTPS 等效安全性的结论。
- 代码开关必须按功能与角色划分，不得用 HTTPS 是否配置统一关闭认证或写操作。
- Issue 08 继续负责目标环境和分角色验收，但不再将备案或 HTTPS 作为验收目标。
